# 1. Modelo verbal del sistema

## Problema actual

Muchos restaurantes gestionan sus pedidos mediante llamadas, mensajes de WhatsApp o notas físicas tomadas por el mesero. Esto dificulta el registro, seguimiento y coordinación de los pedidos.

## Causas identificadas

- No existe un canal centralizado para consultar el menú actualizado y realizar pedidos.
- El registro manual puede generar errores en cantidades, productos y direcciones.
- El cliente no tiene visibilidad en tiempo real del estado del pedido.
- La asignación de domiciliarios se realiza de forma informal.
- No existe un histórico digital consolidado de pedidos y clientes.

## Impacto

- Pérdida de tiempo.
- Errores operativos en la toma de pedidos.
- Insatisfacción del cliente por falta de información.
- Incertidumbre en los tiempos de entrega.
- Dificultad para mantener actualizado el menú.
- Ausencia de datos históricos para analizar el comportamiento de compra.

## Flujo actual

1. El cliente contacta al restaurante.
2. Consulta el menú.
3. El personal registra el pedido manualmente.
4. Se calcula el total.
5. Se prepara el pedido.
6. Se busca un domiciliario disponible de manera informal.
7. El cliente recibe el pedido sin visibilidad del proceso intermedio.

## Solución propuesta

Desarrollar un sistema de pedidos donde:

- El cliente pueda registrarse, consultar el menú, realizar pedidos y hacer seguimiento.
- El administrador pueda gestionar productos, precios, disponibilidad y asignar domiciliarios.
- El domiciliario pueda consultar sus entregas y actualizar su estado.

La solución busca centralizar el proceso, reducir errores y mejorar la experiencia del cliente y del restaurante.
